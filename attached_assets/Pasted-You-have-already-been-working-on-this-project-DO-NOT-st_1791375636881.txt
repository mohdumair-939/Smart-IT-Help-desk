# PROJECT

Official title:

**Smart Help Desk Ticketing System for IT Services**

But this should NOT look or behave like a generic traditional help-desk system.

The core differentiator is:

> **AI-first problem understanding + RAG-based resolution + intelligent escalation.**

The system should try to solve an employee's IT problem before creating/escalating a conventional support ticket.

---

# 1. AI-FIRST USER EXPERIENCE

Instead of immediately showing:

"Create Ticket → Enter Title → Enter Description"

the system should provide an **AI Support Assistant**.

Example:

Employee:

> "My VPN isn't working."

AI:

> "I can help you troubleshoot this. When did the problem start?"

Employee:

> "Since this morning."

AI:

> "Were you able to connect to the VPN before today?"

Employee:

> "Yes."

AI:

> "Are you connected to the internet normally?"

Employee:

> "Yes."

AI:

> "Did you recently change your password or MFA settings?"

The assistant should dynamically ask relevant questions such as:

* What exactly is the problem?
* When did it start?
* Was it working previously?
* What changed before the issue occurred?
* Is the issue affecting only you or multiple users?
* What device are you using?
* What operating system?
* What error message do you see?
* What troubleshooting steps have you already tried?

DO NOT ask every question every time.

Questions should depend on the issue.

---

# 2. AI SHOULD UNDERSTAND THE ISSUE

From the conversation, generate a structured internal problem representation:

* Problem summary
* Category
* Department
* Possible issue type
* Symptoms
* Timeline
* Device/environment
* Error message
* Troubleshooting already attempted

Example:

```text
Problem:
VPN connection failure

Category:
Network / Remote Access

Symptoms:
VPN fails to connect

Started:
Today

Previous state:
Worked previously

Internet:
Working

Possible cause:
Authentication/MFA/VPN configuration

Recommended department:
Network / IT Support
```

This information should automatically become part of the ticket if escalation is required.

---

# 3. RAG SHOULD TRY TO SOLVE THE ISSUE

After understanding the problem:

AI → RAG → Knowledge Base

The system should:

1. Convert the problem into a meaningful retrieval query.
2. Search the vector database.
3. Retrieve relevant knowledge-base chunks.
4. Evaluate whether the retrieved information is sufficiently relevant.
5. Generate a grounded solution using the retrieved information.
6. Show the supporting sources.

Example:

```text
User Problem
      ↓
AI Understanding
      ↓
Relevant Questions
      ↓
Structured Issue
      ↓
RAG Retrieval
      ↓
Relevant Knowledge
      ↓
AI Solution
```

The AI solution must be based on the actual knowledge base.

DO NOT fabricate solutions or citations.

---

# 4. SOLUTION CONFIDENCE / RESOLUTION DECISION

The system needs a clear decision mechanism.

There should effectively be three outcomes:

### CASE A — SOLVED

RAG finds sufficiently relevant information.

AI provides:

* explanation
* troubleshooting steps
* source documents
* next steps

Then ask:

> "Did this solve your issue?"

If YES:

* mark the interaction as resolved
* optionally create a resolved ticket/history record
* store the resolution
* record the interaction in activity history

---

### CASE B — NEEDS MORE INFORMATION

If the AI is uncertain but can reasonably continue troubleshooting:

Ask additional targeted questions.

Example:

> "I found a possible solution, but I need to know which VPN client you are using."

Continue the conversation.

---

### CASE C — AI CANNOT SOLVE

If:

* no relevant knowledge is retrieved
* retrieval relevance is too low
* the issue requires human intervention
* troubleshooting fails
* the user says the solution didn't work

then automatically transition to:

**INTELLIGENT ESCALATION**

---

# 5. INTELLIGENT ESCALATION

This is one of the project's major differentiating features.

Do NOT simply assign every failed ticket to "IT Support."

The system should determine the appropriate department based on the issue.

Example:

VPN → Network / IT Support

Database connection → Database

Suspicious login → Security

Cloud service unavailable → Infrastructure / Cloud

Laptop hardware failure → IT Support / Hardware

Email problem → IT Support

Access permission → IT / Security

The AI should produce:

```text
Detected Department:
Network

Reason:
The issue concerns VPN connectivity and remote access.

Priority:
High

Escalation Reason:
No sufficiently relevant knowledge-base solution found.
```

Then automatically assign/route the ticket.

---

# 9. UNIQUE FEATURE — KNOWLEDGE GAP DETECTION

When RAG cannot solve an issue, don't just escalate it.

Record that the knowledge base was insufficient.

Create an internal concept such as:

**Knowledge Gap Detected**

Example:

> "No sufficiently relevant knowledge article was found for this issue."

Admins should be able to see recurring knowledge gaps.

This allows the organization to identify:

* missing documentation
* frequently unresolved problems
* frequently escalated issues

This makes the project more than a ticketing system.

---

Do NOT claim that the model automatically retrains itself.

```text
Ticket Resolved

Engineer Resolution
      ↓
Resolution Reviewed
      ↓
Admin can convert resolution into
Knowledge Base Article
      ↓
Future RAG searches can use it
```

**"Add Resolution to Knowledge Base"**

button for authorized users.

This creates a useful organizational knowledge loop.
